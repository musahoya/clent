# 🤖 서브 에이전트(Sub-Agent) 개념 이해하기

## 서브 에이전트란?

**서브 에이전트**는 메인 AI 에이전트가 복잡한 작업을 더 작은 전문화된 작업으로 나누어, 각각의 전문 에이전트에게 위임하는 패턴입니다.

### 🎯 왜 서브 에이전트를 사용할까?

#### 1. **컨텍스트 효율성**
- LLM은 한 번에 처리할 수 있는 정보량(컨텍스트)에 제한이 있습니다
- 큰 작업을 작은 작업으로 나누면 각 작업이 필요한 컨텍스트만 사용합니다

#### 2. **전문화**
- 각 서브 에이전트는 특정 작업에 최적화된 지침을 가집니다
- 예: 코드 리뷰 전문, 테스트 작성 전문, 문서화 전문

#### 3. **병렬 처리**
- 여러 서브 에이전트를 동시에 실행할 수 있습니다
- 작업 속도가 크게 향상됩니다

## 🏗️ 실생활 비유

레스토랑을 생각해보세요:

```
손님: "풀코스 요리를 주세요"
         ↓
매니저 (메인 에이전트): 주문을 받고 각 파트에 지시
         ↓
    ┌────┴────┬────────┬──────────┐
    ↓         ↓        ↓          ↓
  샐러드   메인 요리   디저트    음료
  셰프      셰프      셰프      바텐더
(서브에이전트)(서브에이전트)(서브에이전트)(서브에이전트)
```

각 셰프는 자신의 전문 분야만 담당하여 효율적으로 일합니다!

## 💡 Claude Code에서의 서브 에이전트

Claude Code는 다음과 같은 내장 서브 에이전트를 제공합니다:

- **Explore**: 코드베이스 탐색 전문
- **Plan**: 구현 계획 수립 전문
- **general-purpose**: 범용 복잡한 작업 처리

### 사용 예시

```markdown
메인 에이전트: "웹사이트를 만들어주세요"
    ↓
1. Plan 에이전트 호출 → 구현 계획 수립
2. Explore 에이전트 호출 → 기존 코드 패턴 탐색
3. 메인 에이전트가 계획에 따라 코드 작성
4. 테스트 실행
```

## 🎨 커스텀 서브 에이전트 만들기

`.claude/agents/` 디렉토리에 마크다운 파일을 만들면 됩니다:

```markdown
# 예: .claude/agents/ui-designer.md

당신은 UI 디자인 전문 에이전트입니다.

## 역할
- 사용자 경험을 최우선으로 고려
- 접근성과 반응형 디자인 적용
- 최신 디자인 트렌드 반영

## 작업 방식
1. 요구사항 분석
2. 컴포넌트 구조 설계
3. 스타일링 적용
4. 접근성 검증
```

## 🚀 이 프로젝트의 데모

이 프로젝트는 서브 에이전트 개념을 2가지 예제로 보여줍니다:

### 1. **웹사이트 빌더 시뮬레이션**
   - 기획 에이전트
   - 디자인 에이전트
   - 개발 에이전트
   - QA 에이전트

```bash
node demo.js
# 또는
npm start
```

### 2. **🎙️ 자동 뉴스 방송 제작 파이프라인** ⭐ NEW!
   - 📰 뉴스 수집 에이전트 (RSS/API에서 뉴스 가져오기)
   - ✂️ 편집자 에이전트 (방송용으로 선별 및 구성)
   - 📝 대본 작가 에이전트 (TTS 최적화 대본 작성)
   - 🎙️ 음성 변환 에이전트 (텍스트 → 음성 파일)

```bash
node news-pipeline-demo.js
# 또는
npm run news
```

**실전 활용:** 매일 자동으로 뉴스를 수집하고 음성 방송을 만들어 팟캐스트/유튜브에 업로드하는 자동화 시스템!
